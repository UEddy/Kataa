# AuditKIT evaluation (recorded runs)

Generated by `python -m kataa.eval.auditkit_eval`. Episodes are read with `auditkit.agent_eval.episodes_from_agenttune`; the verified outcome is a versioned `CustomPredicate` (`kataa-verified-2`) on AuditKIT's own parse of the tool calls, checked against the environment's ground truth. Tool scores are diagnostics. Comparisons: `ak.compare` (`RunComparison`) gives the paired deltas. **Its p-values are not usable**: at the pinned AuditKIT commit `paired_bootstrap` resamples the raw paired differences without centring them under the null, so p is about 0.5 for any effect and 1.0 when every pair improves (pinned in `tests/test_auditkit_eval.py`). This is a known bug ([AuditKIT issue #20](https://github.com/Lexsi-Labs/AuditKIT/issues/20)), fixed upstream after the pinned 1.1.3; its p-values are recorded but not used. The 95% CIs beside them are Kataa's paired bootstrap (`kataa.eval.stats`, 10,000 resamples) on the same AuditKIT verdicts. Translated sets exclude the task IDs in `data/translations/exclusions.json`. `dpo_rejected` is the DPO repair the gate rejected, shown for the record.

**Decision definitions.** AuditKIT verdicts use the first decision the environment accepted (exactly `loan_id` for this task and a string `reason`), i.e. the recorded state. Kataa's headline scorer is stricter: a malformed first decision call counts as no decision even if a later retry was accepted. The last column lists every task where the two differ.
